# Кадр — React Midterm

Каталог фильмов Studio Ghibli: список, подробности фильма и добавление своих фильмов. React SPA без собственного backend, созданная через официальный `npm create vite@latest -- --template react` (JavaScript). Точка входа и конфигурация взяты из шаблона; добавлены структура из practice, CSS Modules, алиас и проверки.

- Репозиторий: https://github.com/azzarett/react-kbtu/tree/main/midterm
- Приложение: https://azzarett.github.io/react-kbtu/
- Дополнительный адрес: https://azzarett.github.io/react-kbtu/modterm/

Исходники находятся в **midterm**. Приложение открывается на главной странице GitHub Pages; прежний путь **modterm** также работает.

## Данные и возможности

Единственный внешний источник — [Studio Ghibli API](https://ghibliapi.vercel.app/), публичный API без ключа. `GET /films` загружает каталог, `GET /films/:id` — подробности. На момент разработки API содержит 22 фильма. Условие задания о 100 начальных записях относится к собственному или симулированному API, здесь используется внешний публичный API.

- Поиск по названию, оригинальному названию и режиссёру без учёта регистра.
- Совместные фильтры: режиссёр, минимальная оценка и источник (Studio Ghibli / мои фильмы).
- Сортировка по году в обоих направлениях, рейтингу и названию. Числа сравниваются как числа.
- Пагинация по 8 фильмов. Сначала применяются поиск, фильтры и сортировка ко всему списку, затем выбирается страница. Изменение условий возвращает на первую страницу.
- Контролируемая форма: название, режиссёр, год, длительность, оценка, описание. Валидация, сообщения об ошибках и успешном добавлении.
- Состояния загрузки, ошибки с повтором, пустого результата и успеха. Запрос ограничен 15 секундами. При недоступном изображении показывается оформленная заглушка.
- Адаптивная сетка, доступные подписи полей, клавиатурный фокус и `aria-live` / `alert` для сообщений.

API доступен только для чтения. Форма добавляет личный фильм в общую коллекцию и сохраняет его в `localStorage` под ключом `midterm-local-films-v1`. Это локальное пользовательское дополнение, не второй сервер и не симуляция API: нет фальшивых запросов, искусственных задержек или начальной локальной базы. Фильм помечается «Мой фильм», его оценка обозначена как личная. Такие данные доступны только в том же браузере и origin. Очистка данных сайта удалит личные фильмы. Ошибки чтения/записи не затирают данные; при ошибке сохранения форма сохраняет черновик. Названия и описания API оставлены на исходном английском языке.

## Архитектура как в practice

```text
src/
  main.jsx                         # Vite entry, createRoot, StrictMode
  App.jsx                          # Подключение feature и общих стилей
  common/
    components/ui/
      button/                      # Компонент + CSS Module + index.js
      feedback/
      poster/
      pagination/
    styles/
      tokens.css
      base.css
  features/films/
    films-view.jsx                 # Состояние коллекции, фильтров, страницы, экрана
    films-view.module.css
    api/films-api.js               # fetch, ошибки, timeout, нормализация
    model/
      catalog.js                   # Чистые функции поиска/сортировки/валидации
      local-films.js               # Хранение только пользовательских добавлений
    components/
      site-header/
      collection-hero/
      film-filters/
      film-list/
      film-card/
      film-details/
      film-form/
```

Компоненты именуются в kebab-case, CSS Modules лежат рядом. Общий UI импортируется через `@/common/...` и `index.js`, внутри feature — относительные импорты. `common` не зависит от features, features не импортируют друг друга или App. `scripts/check-architecture.mjs`, перенесённый из practice-4, проверяет эти границы.

## React и защита

- `FilmsView` хранит общие данные и условия списка. Черновик и ошибки формы принадлежат `FilmForm`; результат запроса подробностей — `FilmDetails`; ошибка картинки — `Poster`.
- Props передают данные вниз, callbacks сообщают родителю о выборе, фильтрации и создании. State обновляется иммутабельно. Отсортированный список и страницы вычисляются из state, а не дублируются в нём.
- Эффект списка зависит от `[revision]`: изменение счётчика повторяет загрузку. Эффект подробностей зависит от `[selected.id, selected.source, retry]`. Локальная запись не требует сетевого запроса.
- Каждый сетевой эффект создаёт `AbortController` и флаг `active`. Cleanup отменяет запрос и запрещает устаревшему ответу менять состояние. Это также корректно обрабатывает дополнительный setup/cleanup в StrictMode.
- Карточки имеют стабильный `key={film.id}`. Подробности имеют тот же ключ: выбор другого фильма создаёт новый компонент, сбрасывает состояние запроса и очищает предыдущий эффект. Форма размонтируется при отмене/сохранении, поэтому при следующем открытии черновик новый. Фильтры и страница живут выше и сохраняются при просмотре подробностей.
- Обработчик видит snapshot state своего render. Функциональные обновления (`setRevision(value => value + 1)`, добавление фильма через `current`) используют последнее значение. React объединяет обновления внутри события (batching). Изменение state вызывает render; commit применяет результат к DOM; эффекты выполняют синхронизацию после commit.
- Ручного управления DOM нет: единственное обращение к DOM — `createRoot` в шаблонной точке входа Vite.

## Проверки и демонстрация

`npm test` запускает Node tests: комбинации поиска/фильтров/сортировки, границы пагинации, валидация, сохранение, повреждение/переполнение хранилища, нормализация API, HTTP/network ошибки и отмена запроса. Линтер проверяет rules-of-hooks и exhaustive-deps.

Сборка проверена в Chromium с реальным API: список и детали, страницы, поиск и фильтры, валидация формы, добавление и сохранение после перезагрузки, ошибка HTTP 503 и повтор запроса, экран шириной 390 px. Ошибок JavaScript и горизонтальной прокрутки не обнаружено.

1. Откройте коллекцию, переключите страницу; найдите `Miyazaki`, задайте рейтинг 90+, измените сортировку, сбросьте фильтры.
2. Откройте фильм; вернитесь и откройте другой. Для наблюдения cleanup включите Slow 3G в DevTools и вернитесь до завершения запроса.
3. Введите несуществующее название — появится пустое состояние.
4. Отправьте пустую форму — появятся ошибки. Заполните все поля, добавьте фильм, откройте его и перезагрузите страницу. Выберите «Мои фильмы»: запись сохранена.
5. В DevTools включите Offline и нажмите «Обновить»: появится ошибка. Верните Online и нажмите «Попробовать снова».
6. Проверьте интерфейс на узком экране и переходы с клавиатуры.

## GitHub Pages

Корневой `.github/workflows/deploy-pages.yml` запускается при push в `main`, устанавливает зависимости через `npm ci`, проверяет и собирает проект. Содержимое `midterm/dist` копируется в корень `_site` и в `_site/modterm`. Главная страница GitHub Pages открывает midterm напрямую. Существующие практики остаются доступны по своим путям. `base: './'` обеспечивает корректные пути к ресурсам в подпапке. Сервер, ключи API и `.env` не требуются.

Для сдачи нужны ссылка на репозиторий и публичное приложение, затем самостоятельное нажатие Turn in до дедлайна. Подготовка к защите и отправка в учебной системе остаются за студентом.
