# Полка — Async React: Effects & API

Практическая работа №4. React + Vite, JavaScript, CSS Modules. Проект создан через `create-vite --template react`.

## Запуск

Node.js 22.12+ (в CI используется Node.js 24).

```sh
cd practice-4
npm ci
npm run dev
```

```sh
npm run lint
npm test
npm run build
npm run preview
```

## Что реализовано

- Загрузка списка через `useEffect`, кнопка «Обновить» и отдельный асинхронный запрос подробностей выбранной книги.
- Создание, редактирование и удаление с подтверждением; отдельное действие «Отметить прочитанной» через API.
- В карточке отображаются название, автор, описание, жанр, год первого издания, количество страниц, язык, издательство, статус и дата обновления. Список получает только `id`, название, автора, жанр и статус; остальные данные приходят с запросом карточки.
- Состояния загрузки, ошибки с повтором, пустой библиотеки и успешных операций. При ошибке сохранения черновик формы остаётся на месте.
- Имитация API на Promises со случайной задержкой 500–3000 мс и вероятностью ошибки 5%. Данные сохраняются в `localStorage` только внутри API.
- Защита от устаревших ответов, очистка эффектов и блокировка конфликтующих изменений. Во время сохранения можно переключать книги.
- Адаптивный интерфейс, подписи полей, клавиатурный фокус и сообщения `status` / `alert`.

Используются только `useState` и `useEffect`. Custom hooks, `useRef`, `useMemo`, Context, debounce и библиотеки запросов отсутствуют.

Задание разрешает реализовать аналогичные механики [starter fake-api](https://github.com/leravanna/fake-api). Здесь используется собственный API для книг с теми же принципами и поддержкой `AbortSignal`. Это локальная имитация сервера: данные отдельные для каждого браузера и origin. Объём страниц и издательства в начальных примерах условные.

Внутри feature используются относительные импорты. Общий UI импортируется через `@/common/...` и `index.js`. Алиас `@/` настроен в Vite и `jsconfig.json`. В отличие от practice-3, состояние не вынесено в custom hook, поскольку это запрещено заданием. Общие данные хранятся в `BookshelfView`, черновик — в `BookForm`, состояние запроса карточки — в `BookDetails`.

## Объяснение для защиты

### useEffect и зависимости

`useEffect` запускает синхронизацию с внешней системой после commit. Функция эффекта не объявлена `async`: она запускает Promise и синхронно возвращает cleanup.

- Список: зависимости `[revision, mutation]`. При первом монтировании и обновлении загружается список. Пока идёт изменение, чтение приостановлено; предыдущий запрос отменяется. После завершения операции список снова запрашивается.
- Карточка: `[id, retry]`. Загружается только выбранный ID; счётчик `retry` позволяет повторить неудачный запрос.
- Изменение: `[mutation]`. Событие клика создаёт команду с видом операции, ID и данными; эффект выполняет её. Переключение выбранной книги не перезапускает изменение.

Зависимости перечислены полностью. Линтер проверяет `react/exhaustive-deps` и `react/rules-of-hooks`. Состояние загрузки устанавливается при соответствующем действии или инициализации компонента.

### Cleanup и StrictMode

Каждый эффект запроса создаёт `AbortController` и локальный флаг `active`. Cleanup устанавливает `active = false` и вызывает `abort()`: таймер удаляется, Promise отклоняется с `AbortError`, отменённое изменение не записывается в хранилище. `AbortError` не показывается пользователю как ошибка сервера.

Флаг защищает и от запоздавшего результата API, если транспорт не поддерживает отмену. В разработке `StrictMode` выполняет дополнительный цикл setup → cleanup → setup. Первый запрос отменяется; второй обрабатывается обычным образом.

### Race conditions

Если запрос A медленный, а запрос B быстрый, ответ A не должен заменить B. `BookDetails` имеет ключ `${selectedId}:${revision}`: при переключении старая карточка размонтируется, её cleanup отменяет запрос и запрещает обработку результата. Новая карточка сразу показывает загрузку, без данных предыдущей книги. После изменения или ручного обновления карточка загружается заново.

Чтение списка, начатое до изменения, тоже отменяется. API читает актуальное хранилище в момент завершения задержки, а не при старте, поэтому параллельные операции над разными книгами не затирают друг друга.

### Stale closures

При клике команда сохраняет `id`, `title`, `values` и текущий выбор. После ожидания код обращается к этому ID, а не к выбранной в тот момент книге. Ответ обновляет список функциональным `setBooks(current => ...)`, сопоставляя `book.id` с ID команды.

При удалении `setSelectedId(current => current === id ? null : current)` снимает выбор только с удаляемой книги. Если пользователь уже выбрал другую, её карточка остаётся открытой. Во время операции запрещены повторное сохранение, создание, редактирование, удаление и обновление списка; выбор другой книги доступен.

## Как продемонстрировать

1. Выберите книгу: сначала появится загрузка, потом подробная карточка.
2. Быстро выберите несколько разных книг: отображаться должна только последняя выбранная.
3. Нажмите «Отметить прочитанной» и сразу выберите другую книгу. Изменится статус исходной книги, выбор останется на новой.
4. Создайте книгу, измените описание и перезагрузите страницу: данные сохранятся.
5. Удалите книгу; удалите все книги и перезагрузите страницу: появится пустое состояние, примеры не восстановятся автоматически.
6. В `api/settings.js` задайте `errorChance: 1`, чтобы гарантированно показать ошибки списка, карточки и сохранения. Затем верните `0` и повторите действия. После демонстрации восстановите `0.05`.
7. Для длинных запросов увеличьте `minDelay` / `maxDelay`, например до 2000 / 8000 мс. После демонстрации верните 500 / 3000.

Для сброса примеров можно удалить только ключ `practice-4-books-v1` в DevTools → Application → Local Storage и обновить страницу. Компоненты напрямую к хранилищу не обращаются.

## Проверки

`npm test` запускает 7 тестов API через встроенный `node:test`: поля списка и карточки; CRUD и пустая библиотека; завершение операций в другом порядке; отмена чтения и записи; ошибки сервера и повтор; валидация и повреждённые данные; недоступное / переполненное хранилище.

Проверка интерфейса в браузере включает быстрое переключение карточек с запоздавшим ответом, смену выбора во время завершения и удаления, блокировку конфликтующих действий, повтор ошибок списка/карточки/сохранения, CRUD, перезагрузку страницы и мобильную форму.
