# Полка — дневник чтения

Практическая работа №3: Rendering and State. SPA на React и Vite, JavaScript и обычный CSS.

## Запуск

Node.js 22.12+ или 24 LTS.

```sh
cd practice-3
npm ci
npm run dev
```

Проверки и production-сборка:

```sh
npm run lint
npm run build
npm run preview
```

## Возможности

- Добавление книги с названием, автором, жанром и количеством страниц; удаление книги.
- Три статуса: «Хочу прочитать», «Читаю», «Прочитано».
- Прогресс чтения: ввод текущей страницы или кнопка «+10» с ограничением по объёму книги.
- Личная заметка у каждой книги.
- Фильтр по статусу и поиск по названию / автору.
- Обратный порядок списка: сначала старые или сначала новые.
- Сброс прогресса и заметки одной книги кнопкой со стрелкой рядом с «+10».
- Сохранение локального состояния при фильтрации, поиске и перестановке.
- Пустые состояния, адаптивная верстка, подписи полей и клавиатурный фокус.

Статус выбирается вручную и не зависит от текущей страницы. Сброс обнуляет прогресс и заметку, сохраняя статус. Все данные живут в памяти до обновления страницы. Количество страниц в начальных примерах условное и зависит от издания.

## Архитектура: common + features

Структура повторяет `practice-2`: функциональность сгруппирована в `features`, общие UI-компоненты и стили — в `common`. Имена файлов компонентов — в kebab-case, рядом с каждым компонентом находится его CSS Module.

```text
src/
  App.jsx                         # Подключение экрана и глобальных стилей
  main.jsx                        # Точка входа, StrictMode
  common/
    components/ui/
      button/                     # Общая кнопка и её варианты
      empty-state/                # Пустое состояние с действием
      visually-hidden/            # Доступные скрытые подписи
    styles/
      tokens.css                  # Цвета и шрифты
      base.css                    # Сброс и базовые стили
  features/bookshelf/
    bookshelf-view.jsx            # Сборка экрана из компонентов
    bookshelf-view.module.css
    hooks/use-bookshelf.js        # Состояние коллекции и действия над ней
    constants/
      books.js
      statuses.js
    components/
      site-layout/                # Шапка и подвал
      library-header/             # Заголовок и открытие формы
      library-summary/            # Счётчики книг
      book-filters/               # Статус, поиск и порядок
      book-list/                  # Список, стабильные ключи и скрытие строк
      book-row/                   # Локальные page, note, noteOpen
      add-book-form/              # Форма и локальная ошибка валидации
```

`App` подключает `BookshelfView`. Экран использует `useBookshelf` и передаёт данные и обработчики дочерним компонентам через props. Custom hook хранит родительское состояние в компоненте, который его вызывает; он не создаёт отдельное хранилище. Прогресс и заметка остаются внутри `BookRow`.

Зависимости направлены от приложения к `features` и `common`. `common` не импортирует функциональность библиотеки, а отдельные features не импортируют друг друга. Команда `npm run lint` запускает Oxlint и `scripts/check-architecture.mjs`, который проверяет эти границы по тем же правилам, что и в `practice-2`.

Алиас `@/` указывает на `src/` и настроен в Vite и `jsconfig.json`. Внутри feature используются относительные импорты, общие UI-компоненты доступны через свои `index.js`. Глобальными остаются только токены, сброс и базовая типографика; оформление компонентов и медиазапросы находятся в соответствующих CSS Modules.

Используются функциональные компоненты, `useState`, props, условный рендеринг и `.map()`. Redux, Context, внешние хранилища состояния и `useEffect` не используются.

### Как работают keys

Ключ строки — `${book.id}:${book.edition}`. `id` у новой книги создаётся один раз через `crypto.randomUUID()`. При перестановке ключ остаётся прежним, поэтому React сопоставляет строку с той же книгой и сохраняет её локальное состояние. Индексы массива в качестве ключей не используются.

При фильтрации **все компоненты книг остаются смонтированными**. Неподходящие строки получают HTML-атрибут `hidden` и исчезают из интерфейса и дерева доступности. Один лишь стабильный `key` не сохранит локальный state после размонтирования: поэтому нельзя здесь отфильтровать массив перед `.map()`. Для небольшой учебной библиотеки этот подход позволяет держать прогресс непосредственно внутри дочернего компонента.

Сброс увеличивает `edition` только выбранной книги и задаёт ей `initialPage: 0`. Изменение ключа заставляет React удалить старый экземпляр `BookRow` и создать новый. Все его `useState` инициализируются заново: страница становится нулевой, заметка очищается, её поле закрывается. Другие книги сохраняют свои ключи и состояние.

### Рендеринг и reconciliation

В телах `BookshelfView` и `BookRow` есть `console.log()`. Откройте консоль браузера:

1. Нажмите «+10»: обновится локальный `page`, в консоли появится рендер этой книги. Родительский `BookshelfView` не обновляется.
2. Измените статус или фильтр: обновится состояние `BookshelfView` через `useBookshelf`, и экран заново вызовет дочерние компоненты. Повторный рендер сам по себе не сбрасывает их state.
3. Разверните список: ключи помогут React сопоставить книги и переставить их DOM-узлы.
4. Сбросьте одну книгу: изменится её ключ, React создаст новый экземпляр компонента.

Рендер вычисляет описание интерфейса. Reconciliation сопоставляет старое и новое дерево по типам компонентов, их позиции и ключам. В DOM применяются только нужные изменения. В режиме разработки `StrictMode` может вызывать рендер повторно; поэтому повторные сообщения в консоли ожидаемы. Это не означает, что на странице появятся дубликаты.

## Проверка перед защитой

1. У «Норвежского леса» добавьте 10 страниц и напишите заметку.
2. Выберите «Хочу прочитать», затем «Все книги»: прогресс и заметка должны сохраниться.
3. Найдите другую книгу и очистите поиск: состояние первой книги также сохраняется.
4. Переключите порядок: прогресс и заметка должны остаться у своей книги.
5. Измените статус в активном фильтре: книга скроется, но сохранит локальное состояние.
6. Сбросьте одну книгу: только её прогресс и заметка обнулятся.
7. Добавьте и удалите книгу. Проверьте пустой список и поиск без результатов.
