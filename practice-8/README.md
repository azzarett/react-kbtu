# Полка · Практика 8

Книжная полка на React, Vite и Redux Toolkit. В личной библиотеке можно добавлять книги, менять статус чтения, искать по автору или названию и смотреть статистику. Мировой каталог загружает данные из Open Library.

[Открыть на GitHub Pages](https://azzarett.github.io/react-kbtu/practice-8/) · [Исходный код](https://github.com/azzarett/react-kbtu/tree/main/practice-8)

## Запуск

Используйте Node.js 24.15+ из ветки 24 LTS. Запуск из корня репозитория выполняется следующими командами.

```sh
cd practice-8
npm ci
npm run dev
```

Для локального входа через Firebase задайте параметры своего Firebase Web App в `.env.local` по образцу `.env.example`. Для Email/Password и Google включите соответствующие провайдеры в Firebase Authentication и добавьте домен приложения в Authorized domains. При публикации GitHub Actions передаёт существующие параметры `VITE_FIREBASE_*` на этапе сборки.

## Redux Toolkit

`src/store/store.js` объединяет три слайса через `configureStore`. Компонент `App` создаёт store один раз за время жизни приложения и передаёт его маршрутам через `Provider`. Компоненты получают данные через `useSelector` и отправляют действия через `useDispatch`.

| Слайс | Что хранит | Асинхронные операции |
| --- | --- | --- |
| `bookshelf` | Полные записи локальной полки, состояние чтения и текущей записи | `loadBooks` загружает коллекцию. `saveBook` создаёт, редактирует и удаляет книгу или меняет статус чтения. Успешная запись возвращает сохранённую коллекцию и сразу обновляет список, карточку и статистику. |
| `catalog` | Текущая выдача Open Library и открытая карточка с отдельными статусами и ошибками | `fetchCatalogSearch` ищет книги по тексту и номеру страницы. `fetchCatalogBook` получает подробности по идентификатору произведения. |
| `connectivity` | Доступность сети, статус проверки соединения и источник данных каталога | `checkConnection` проверяет файл на сервере в обход кэша. Сообщения service worker обновляют индикатор, когда каталог загружен из сети или из сохранённой копии. |

Все пять операций используют `createAsyncThunk`. Слайсы обрабатывают `pending`, `fulfilled` и `rejected` в `extraReducers`. Идентификатор запроса защищает текущий экран от запоздалого ответа. Кнопки повтора запускают новое чтение. Каталог объединяет одинаковые параллельные запросы и повторно использует успешный ответ в течение минуты.

### Селекторы

В `src/features/bookshelf/state/bookshelf-selectors.js` коллекция служит единственным источником для представлений полки. Мемоизированные через `createSelector` селекторы возвращают прежний результат, пока их входные данные совпадают.

- `selectBooksPage` применяет поиск, фильтры и сортировку, затем выбирает текущую страницу.
- `selectDashboard` вычисляет статистику и список книг для выбранных жанра и статуса.
- `selectBookDetails` находит книгу по ID, а `selectBookGenres` формирует список жанров для фильтра.
- `selectCatalogSearch` и `selectCatalogBook` выбирают результат для текущего адреса. `selectConnectivity` используется в индикаторе сети и на странице офлайн-режима.

### Границы состояния

Поиск, фильтры, сортировка и страница живут в URL. В мировом каталоге набор текста запускает поиск после паузы в 350 мс, а отправка формы выполняет его сразу. Маршруты используют `HashRouter`, поэтому прямую ссылку на карточку можно открыть и обновить на GitHub Pages.

Формы, подтверждение удаления и события установки PWA остаются локальными. `AuthContext` подписывается на Firebase и защищает маршрут `/#/profile`. Полка хранится в браузере и доступна пользователям этого профиля браузера. При первом открытии практика 8 копирует существующую коллекцию из практики 7, если обе открыты на одном origin. Дальнейшие изменения записываются в `practice-8-books-v1`.

## Офлайн и проверка

После первой успешной загрузки service worker сохраняет оболочку приложения и файлы всех маршрутов. Локальные CRUD-операции доступны офлайн. Для поиска и карточек Open Library доступны ранее загруженные ответы за последние 24 часа, до 50 запросов. Вход через Firebase требует сети.

```sh
npm run check
npm run preview
```

`check` запускает линтер, проверку границ `common` и `features`, тесты API, Redux и интерфейса, production-сборку и проверку service worker. Для ручной проверки откройте preview, дождитесь активации service worker, отключите сеть, обновите страницу и откройте книгу. Запуск GitHub Actions повторяет проверки перед публикацией в каталоге `/react-kbtu/practice-8/`.
